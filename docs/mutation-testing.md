# Мутационное тестирование домена и usecase

Отчёт для дополнительного задания лабораторной работы 2. Прогон выполнен 10 ноября 2026 года на ветке `homework/02` с Gremlins v0.6.0. Проверены все Go-пакеты в `internal/domain/...` и `internal/usecase/...`: `domain/trip`, `usecase/trip/create`, `usecase/trip/finish`, `usecase/trip/get`.

## Воспроизведение

```bash
go install github.com/go-gremlins/gremlins/cmd/gremlins@v0.6.0
mkdir -p /tmp/tripgo-go-cache
for package in internal/domain/trip internal/usecase/trip/create internal/usecase/trip/finish internal/usecase/trip/get; do
  GOCACHE=/tmp/tripgo-go-cache gremlins unleash "$package" \
    --workers=2 --timeout-coefficient=10 \
    --invert-logical --invert-assignments --invert-loopctrl --remove-self-assignments \
    --output="/tmp/$(basename "$package")-mutation.json"
done
```

Использованы стандартные операторы Gremlins и дополнительные операторы для логических выражений, присваиваний, циклов и удаления самоприсваиваний. Проверка шла по обычным unit-тестам, без тега `integration`. `GOCACHE` вынесен в доступный для записи каталог: с недоступным кэшем ошибки запуска `go test` ошибочно выглядят как убитые мутанты. `--timeout-coefficient=10` исключил ложные таймауты на коротких пакетах.

## Разбор выживших

Оба выживших мутанта находились в `internal/usecase/trip/create/usecase.go:60`, в выражении `now.Add(-idempotencyTTL)`:

| Оператор | Что меняется | Почему это ошибка | Новый тест |
|---|---|---|---|
| `ARITHMETIC_BASE` | отрицательный сдвиг заменяется положительным | Порог истечения ключа переносится на час в будущее, и действующий ключ может быть принят за просроченный | `TestExecuteIdempotencyExpiry` |
| `INVERT_NEGATIVES` | отрицательный сдвиг заменяется положительным | То же поведение; инструмент создаёт второй мутант на том же унарном минусе | `TestExecuteIdempotencyExpiry` |

Тест проверяет, что порог для поиска находится между значениями времени непосредственно до и после вызова `Execute`, с вычетом одного часа. Он также проверяет, что резервирование получает тот же порог. После добавления теста оба мутанта убиты. Необъяснённых выживших мутантов нет.

Дополнительно вручную проверена мутация `now := u.now().UTC()` → `now := u.now()` в том же usecase. Gremlins не генерирует такую мутацию. До изменения тестов она проходила; теперь `TestExecuteCreatesTrip` проверяет UTC у `StartedAt`, и тест падает на этой мутации. Эта ручная проверка не включена в числа таблицы.

Ограничение отчёта: нулевое число выживших относится только к мутациям, которые генерирует Gremlins с указанными операторами. Оно не доказывает отсутствие других пробелов в тестах.
